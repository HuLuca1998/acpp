# ADR-022：别的 AI 的同步问答面 `/api/ask`

日期：2026-09-09　状态：已采纳

## 背景

用户本机的 claude CLI 与 codex CLI 此前靠一个 `codex-collab` skill 互相协作：Claude 把审查 / 咨询 / 干活的任务用 `codex exec` 发给 codex，再用 jq 从事件流里捞正文。它有三处硬伤——

- **单向**：只有 claude → codex，codex 问 claude 没有对应物。要做对称，得再写一套针对 claude CLI 的脚本，两套输出格式、两套沙箱参数各管各的。
- **过程不可见**：codex 在做什么、读了哪些文件、卡在哪，都埋在被过滤掉的事件流里；想追查只能重跑。
- **权限一刀切**：受限沙箱连 `.git` 都是只读，要写就只能 `--yolo`，中间没有档位。

acpp 已经用 ACP 同时会说两家 runtime：会话池、事件归一化、三档权限（adr-011）、权限自动放行（技能包）、转录重建都是现成的。把它当中间人，上面三条都不用再造。

## 决策

1. **只开一个端点 `POST /api/ask`**，请求 `{agent, cwd, prompt, level?, thread?}`，**阻塞到轮末**才回 `{thread, text, stopReason?}`。调用方是脚本，它只认「问一句、拿答案」这一个原语；会话、SSE、权限卡片全在服务端消化。与 adr-021 的 `/api/db` 同一口径：端点少、字段少、内部概念不外露。
2. **每次问答就是一条真实会话**：`thread` 就是 acpp 的会话 id，续聊直接带上；会话带 `origin=ask` 标记入库，界面里能点开看全程，人可以随时接进去继续聊。
3. **权限档复用 adr-011 的三档**，新会话默认 `safe`（只读）。轮内的权限请求由后端替人裁决：`full` 档放行一次、其余档拒绝一次，只选 `*_once` 不落持久规则；交互式提问一律取消——问的人是脚本，没有第二个人能回答。
4. **凭证零个**：回环即 owner（adr-007），本机脚本不需要 token；租户经 cookie / Bearer 也能用，会话按 scope 归属。
5. **不排队**：同一 thread 上一轮没完再问回 409。单轮上限 1 小时；调用方挂断即中止那一轮。
6. **skill 只住在调用方那边**（用户的 hz-agents 仓库），acpp 不预置、不分发它。acpp 会话本就屏蔽机器级技能，被问的一方看不到这个 skill，「AI 问 AI 再问 AI」的套娃在结构上就不成立，不需要 depth 护栏。

## 理由

- 同步长连接优于「建会话 + 发消息 + 订阅 SSE」三步：三步在脚本里意味着 curl 拼 SSE 解析，正是 codex-collab 用 jq 捞事件那套的翻版。服务的 `WriteTimeout` 本就为 SSE 设成 0，长连接不需要额外配置。
- 回答取自转录重建而不是攒流式分片：broker 对慢订阅者会丢事件（`stream.Broker.Publish`），转录才是事实源。`text` 的定义是「最后一条提问之后 agent 说的全部正文」，工具调用之间的段落按序拼接——审查结论常常在最后一段，但中间段也可能有要点，不做取舍。
- 权限自动裁决而不是让请求挂 30 分钟等人：机器调用没人在界面点卡片，挂着只会让整轮卡死到超时。拒绝后 agent 会带着「被拒」继续作答，这比卡死好，也让 `safe` 档真正意味着只读。
- `level` 用 acpp 自己的词汇而不是 codex-collab 的四种「模式」：审查 / 讨论 / 决策三种模式在权限上没有区别，都是只读；模式是 skill 层的方法论（提示词模板、轮数上限），不该泄露到 HTTP 面。

## 后果

- 新增 `internal/ask` 包（`ask.Service`）与 `httpapi/chat.go` 里的 `askHandler`；`model.Session` 加 `origin` 列，前端类型同步。`acp.ErrBusy` 在 `writeError` 里映射为 409。
- 2026-09-09 真机：经 dev 后端分别问 codex 与 claude，会话正常入库、`level=safe` 生效（claude 试写 `/tmp` 被拒并如实汇报）、续聊命中同一会话、同 thread 并发回 409。codex 侧当时撞到模型限流（429），文本原样带回，这正是「过程可见」的价值——错误不会被过滤成沉默。第一版让 claude 审自己，它抓出三处真问题并已修：busy 检查与 Send 之间的竞态（改为包内持锁的在途表）、turn_done 被丢只能等到超时（加 5 秒一次的 TurnActive 兜底探查）、没跑成的新会话残留（即刻收掉）。
- 已知边界：`safe` 档下 agent 仍能读会话目录外的文件（与界面会话一致，adr-007 的执行边界是软的）。要真正的只读隔离需要 OS 级沙箱，不在范围内。
- 回归保护：`httpapi/ask_test.go`（入参校验、agent 寻址、续聊归属闸、请求体不能自报 origin）、`ask/ask_test.go`（`text` 的取法）。真跑一轮的行为靠 skill 的 `ask.sh` 双向真机验证。
