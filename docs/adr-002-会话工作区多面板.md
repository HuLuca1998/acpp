# ADR-002 会话工作区多面板（docking workspace）

- 状态：**已接受**（2026-08-11 技术选型经调研确认，自 M1 动工）
- 日期：2026-08-11
- 关联：[adr-001 codex/claude 差异收敛](adr-001-codex-claude-差异收敛.md)、[README §对话是怎么流起来的](../README.md)

## 1. 背景与目标

AI 会话的工作目录通常是一个 git 仓库。当前会话页只有对话流，用户看不到 agent 对仓库做了什么。目标是把会话页升级为**可自由编排的多面板工作区**：对话之外，提供工作区 diff、文件树、文件预览、终端、未推送 commit 共 6 类面板，全部支持拖动重排、分裂/合组、缩放、显隐，且**流畅顺滑**（性能是一等需求，不是优化项）。

## 2. 产品形态（定稿）

### 2.1 六类面板

| 面板 | 说明 | 可关闭 | 多实例 |
| --- | --- | --- | --- |
| 对话 | 现会话页主体（消息流 + composer） | **否** | 否 |
| 工作区 diff | 未提交变更，文件级折叠 | 是 | 否 |
| 未推送 commit | `@{upstream}..HEAD` 列表，带 ahead 徽标 | 是 | 否 |
| 文件树 | 会话 cwd 的目录树 | 是 | 否 |
| 文件预览 | 只读代码/文件查看 | 是 | 否 |
| 终端 | 真 PTY，会话 cwd 起 shell | 是 | **是**（编号递增，上限配置） |

### 2.2 布局交互模型（VS Code 式 docking）

- 任意面板可拖 tab 到其他面板的上/下/左/右缘**分裂**布局，拖到中央**合组**成 tabs；对话面板除外（不参与合组、不可拖出、不渲染关闭按钮，设最小宽度约 320px）。
- 双击 tab 最大化；布局自动持久化（localStorage），刷新后原样恢复。
- **⋯ 菜单**（对话面板 header 右上角）是窗口管理总入口：
  - 其余 5 类面板的显隐勾选（终端项为子列表：已开实例 + 「新建终端」）；
  - 「布局」一节：内置预设一键切换 + 恢复默认。
- 隐藏的面板记忆原位置，重开回原处；原组不存在则回右侧主组。

### 2.3 初始默认布局（定稿；2026-08-12 变更）

**默认 = 纯对话铺满，工作区面板全部隐藏**。面板一律按需唤起：⋯ 菜单勾选、或联动命令（点文件树里的文件自动开预览等）。首次唤起时在对话右侧新开约 1/4 宽的组，后续面板并入该组成 tabs。

- 旧定稿（对话 80% + 右栏 20% 待命 tab 组）作废：改为纯对话，首屏零工作区开销，复杂度完全由用户自己拉出来；旧形态可用「布局」预设或逐个开面板复现。
- 窄栏（低于阈值）tab 头自动退化为**纯图标**（tooltip 给全名，commit 徽标叠图标角）；拖宽恢复「图标+文字」。
- **惰性激活**：终端 PTY 首次可见才 spawn，git 数据首次激活才拉取。
- 文件树**默认展开 2 层**（接口按 `?depth=2` 一次返回，第三层起点击懒加载），按 `.gitignore` + 固定黑名单（`node_modules/`、`.git/`、`dist/` 等）过滤，留「显示被忽略文件」开关。

### 2.4 内置布局预设

同一布局引擎的四份序列化 JSON，⋯ 菜单一键切换；用户拖动调整后自动保存为「当前布局」，预设只是起点：

- **默认**：即 §2.3 纯对话。
- **A · IDE 经典**：文件树窄列靠左 ｜ 对话居中 ｜ 右 tab 组（diff/commit/预览），终端横贯底部。
- **B · 代码审查**：对话左 36%，右侧大 diff 独占 + commit 伴随，其余隐藏。
- **D · 终端工作台**：上排对话 ｜ 文件树组，下排双终端并排。

### 2.5 多终端语义

- 编号递增（终端 1/2/3…），中途关闭不回填，全关重置；每会话实例上限（`ACP_MAX_TERMINALS`，默认 5）。
- 关闭 tab = 杀 PTY（诚实语义）；ws 断线 ≠ PTY 死——保留进程与输出缓冲约 30s 供重连恢复，超时回收；服务关闭统一回收。
- 恢复布局时 PTY 已死 → 面板显示「会话已结束，回车重启」空态，不假装活着。

## 3. 技术选型

### 3.1 布局引擎：dockview（已确认）

需求是完整 docking（任意分裂/合组/序列化），自研 = 重写一个 mini docking 框架，工时与 bug 面远超刷皮肤成本。2026-08 调研结论（依据见文末 Sources）：

| 候选 | 周下载 | 维护状态 | 否决/入选理由 |
| --- | --- | --- | --- |
| **dockview** ✅ | ~117k | 活跃（3.4k stars，零依赖） | 同类中下载量最高；能力全（tab 合组/分裂/浮动/popout/序列化/触屏） |
| flexlayout-react | ~65k | 活跃 | 企业向偏重，能力与 dockview 重叠但生态更小 |
| rc-dock | 更少 | 一般 | 定位简单 tab 工作区，能力不足 |
| react-mosaic | — | 不活跃 | 无 tab 合组 |
| golden-layout | — | 停滞 | 非 React 原生，官方对比文章亦推荐迁移到上面几家 |
| 自研（react-resizable-panels + 重排） | — | — | 单列抽屉形态下成立；6 块自由 docking 需自研 drop zone/布局树/拖动预览，放弃 |

性能层面的实证：dockview 的 resize 事件本身经 `requestAnimationFrame` 派发（issue #344 维护者说明）；隐藏面板默认卸渲染，且面板级支持 `renderer: 'always'` 保留 DOM（issue #397，正好满足终端保活）；未发现系统性性能投诉，已知 issue 为 flex 容器缩高等边缘案例。这与 §4 的性能模型吻合。

匹配点：零依赖；framework-agnostic core + React 壳（布局模型在 React 外）；overlay 式 drop 预览（拖动不改布局树）；CSS 驱动 resize；`toJSON/fromJSON` 序列化。代价：tab 头与分组 chrome 需用其自定义渲染接口换成本项目样式，动效按 web/AGENTS.md §5.4 覆盖——一次性投入。若实测某环节不达标，其 core 是可替换单点，但**先量再说，不预先自研**。

M1 实测备注（v8.0.0）：

- React 壳在 v8 拆成独立包 `dockview-react`（`dockview` 只是 core 的纯转发）。
- **挂载瞬间容器是 100px 占位尺寸**：onReady 里按比例 `setSize` 会被最小宽度钳死成空操作、落盘均分布局。初始比例必须逐帧等到真实测量（`api.width` 足以容纳各面板最小宽）再应用（见 workspace-dock 的 applyRatio）。
- dockview-react 会无条件注册企业版 ContextMenu 的组件工厂，core 打一条**去重后的** console.error 并把该功能降级为 no-op——我们不用右键菜单，此噪音可忽略，等上游修复。

### 3.2 终端：@xterm/xterm + coder/websocket + creack/pty（已确认）

「真实终端」的技术栈三个环节都取事实标准，调研结论：

- **前端 xterm.js（`@xterm/xterm`）无真正竞争者**：VS Code 集成终端同款，2026 年仍是唯一活跃的全功能 web 终端渲染库（备选 hterm/ttyd 前端等均弱于它）。WebGL addon 是官方 GPU 加速 renderer，「super fast、大 viewport 下扩展性远好于 canvas」；近年默认 DOM renderer 也大幅提速，作为 WebGL 配额降级路径成立（§3.2 配额策略）。
- **后端 ws 库选 `coder/websocket`**（不是 gorilla）：gorilla/websocket 曾于 2022 归档，且并发写会 panic（生产最常见坑）；coder/websocket 活跃维护、context 化 API、内部处理并发写。2025-26 社区共识：新项目用 coder/websocket。
- **PTY 用 `creack/pty`**：Go 生态事实标准（Docker 等在用），纯 Go，无 CGO，与本项目「glebarez/sqlite 纯 Go」的既有取向一致。

- 前端 `@xterm/xterm` + `@xterm/addon-fit` + `@xterm/addon-webgl`；后端 `creack/pty` + `coder/websocket`（项目现仅有 SSE，双向通道是新增）。
- 每终端一条独立 ws（一期不做多路复用）；后端 PTY 注册表（id → 进程），归属会话。
- **WebGL context 配额坑**：浏览器 WebGL context 上限约 8–16 个，超限强制丢失最老 context。策略：仅「当前可见」终端挂 WebGL renderer，隐藏 tab 降级普通 canvas，切换时动态换 renderer；叠加实例上限双保险。

### 3.3 复用与不引入

- diff 渲染复用 `components/chat/tool-call.tsx` 的 `lineDiff`/`DiffView`（抽到共享位置），含超大文件退化策略。
- 语法高亮一期不做（现 markdown 代码块也无高亮库），二期再评估 shiki。
- **不引入**全局状态库、不引入 dnd-kit（dockview 内置拖放；树节点拖拽用原生 pointer）。

## 4. 性能设计（顺滑是架构决定的）

帧预算：120Hz 屏一帧 8.3ms。两条铁律：**拖动路径零 React 渲染、零强制同步布局**；**能只动 transform/opacity 的绝不动布局，必须动布局的把 reflow 圈在最小范围**。

### 4.1 拖动三层管线

```
输入层 pointermove ──► 计算层 纯数学 ──► 应用层 rAF 内写 DOM
（capture、阈值）      （零 DOM 读取）   （每帧最多一写）
```

- 输入层：Pointer Events + `setPointerCapture`（事件不丢）；4–6px 移动阈值防误触；拖动即盖透明 overlay + 内容 `pointer-events: none`（防 xterm canvas 吃事件）+ `user-select: none` + 根节点统一 cursor。
- 计算层：`pointerdown` 一次性快照所有 rect/约束为纯数据，之后每帧只做数学；拖动中**禁止**读布局（防 layout thrashing）。
- 应用层：最新位置存 ref，rAF 每帧取一次写 DOM，丢弃中间值。

### 4.2 两种拖动两套策略

- **tab 重排：拖动中完全不碰布局树。**跟手的是 ghost（fixed + transform）与 drop 高亮层（absolute，transform/opacity），纯合成器操作；真实布局松手才 commit 一次。drop 判定加滞回（进出阈值不同）防边界闪烁。
- **分割线 resize：受控 reflow。**每帧一写 flex-basis；面板内容容器挂 `contain: layout paint` 圈禁 reflow 范围；重内容（终端、diff 列表）与容器解耦——外层 `overflow: hidden`，内容经**节流 ResizeObserver**（100–150ms）跟进，松手终值精确对齐（xterm refit 同此节奏）。min/max 与级联挤压在计算层用快照 clamp，不靠 CSS 兜底（避免指针与分割线脱钩）。

### 4.3 React 隔离

- 拖动状态永不进 React state：全程 ref + DOM 直写，React 只知 dragstart/dragend。
- 布局模型在 React 外（dockview core）；面板内容全 `React.memo` + 稳定 props。
- SSE 高频流（chunk、终端输出）由面板内部局部消费，不经过工作区层；自定义 tab 头拖动期零 setState（悬停用 CSS 伪类）。

### 4.4 各面板内容预算

| 面板 | 手段 |
| --- | --- |
| 对话 | 复用 `MessageScroller`；resize 期间暂停滚动跟随，松手对齐 |
| 终端 | WebGL 自绘零 DOM；xterm 自带输出缓冲合帧；refit 节流 |
| diff | 文件级折叠 + 点开懒加载；大 diff 固定行高虚拟滚动 |
| 文件树 | 目录懒加载限量；固定行高；展开动画只做 opacity |
| 预览 | 大小上限截断；虚拟行渲染二期 |
| 隐藏 tab | DOM 保留（终端不丢状态）+ `content-visibility: hidden` 渲染归零 |

### 4.5 动效收尾

松手后 FLIP：commit 布局→测新位置→受影响面板 transform 过渡（150–250ms `ease-fluid`），ghost 淡出至落点；面板显隐用 opacity + 轻微 scale，不做宽高动画；`motion-reduce` 降级为纯 opacity。全部符合 web/AGENTS.md §5.4。

### 4.6 验收标准（完成定义的一部分）

- 压力场景：5000 行 diff 展开 + 终端刷屏 + 对话流式输出**同时进行**，拖 tab 与拖分割线仍满帧；
- 拖动期帧时长 p95 < 8ms，无 >50ms long task；React Profiler 确认拖动全程 0 次面板重渲染；
- Performance 面板录制无强制同步布局警告；开发模式加 rAF 帧时长埋点，超标 console.warn。

## 5. 面板联动

### 5.1 联动矩阵

| 源 | 动作 | 效果 |
| --- | --- | --- |
| 文件树 | 右键「添加到对话引用」 | composer 出现引用胶囊（文件/文件夹） |
| 文件树 | 拖节点到对话面板 | 同上（drop 即引用） |
| 文件树 | 单击文件 | 预览 tab 打开 |
| 文件树 | 右键「在此打开终端」（文件夹） | 新终端实例，cwd = 该目录 |
| diff | 点文件名 | 预览打开并定位首个变更 |
| commit | 展开提交点文件 | 该 commit 版本单文件 diff |
| 对话 | 点消息/工具调用里的路径 | 文件树 reveal + 预览打开 |
| 预览 | header「添加到引用」 | composer 引用胶囊 |
| 系统 | `turn_done` | diff / commit / 文件树自动刷新 |

### 5.2 工作区命令总线

会话页面层立 `WorkspaceProvider`（面板之上、dockview 之外），持有：

1. **命令表**：`chat.addReference(path, kind)`、`preview.open(path, opts)`、`tree.reveal(path)`、`terminal.create({cwd})`、`git.refresh()`。面板间永不直接对话，发起方只 dispatch。实现为 context + 自写约 20 行 emitter，不引状态库。
2. **`ensureOpen(panelId)`**：命令执行前确保目标面板存在——不存在则经 dockview API 按默认位置创建（预览进文件树同组），面板 ready 后冲刷 pending 命令队列。用户视角「右键点完，该开的自己开好并定位」。
3. **共享数据上提**：`git/overview` 结果、composer 引用列表、`use-chat` 状态机都在 Provider 层，面板只是订阅者（diff 关着时 commit 徽标照样更新；对话面板重挂载引用不丢）。

### 5.3 引用语义

- 复用现有 @ 引用机制（数据结构、胶囊 UI、后端嵌入逻辑），右键/拖拽只是新入口。
- **文件夹引用（新语义，定稿）**：嵌入**目录结构清单**（两层，含文件名与大小）+ 提示「需要内容可自行读取」，不递归嵌全文（token 灾难；agent 自有 fs 能力，给地图优于给全文）。`send` 的 `files` 字段扩展为 `{path, kind: file|dir}`。
- 右键菜单用 shadcn `context-menu`（需 `npx shadcn add`）；菜单项按节点类型：文件 = 引用/预览/复制路径，文件夹 = 引用/在此开终端/复制路径。

## 6. 后端新增

| 端点 | 说明 |
| --- | --- |
| `GET /api/sessions/{id}/git/overview` | 一次返回：分支、upstream、ahead/behind、工作区变更文件、未推送 commit 列表（diff 与 commit 两面板共享） |
| `GET /api/sessions/{id}/git/diff?path=` | 单文件工作区 diff |
| `GET /api/sessions/{id}/git/commits/{sha}?path=` | 某 commit 的 stat / 单文件 diff |
| `GET /api/fs/entries?path=&depth=` | 目录+文件列表（gitignore/黑名单过滤，depth≤2） |
| `GET /api/sessions/{id}/file?path=` | 文件内容（大小上限、二进制检测、cwd path guard） |
| `WS /api/sessions/{id}/terminals/{tid}` | PTY 双向流；配套 POST 创建 / DELETE 关闭 |

- git 操作 shell out 到 `git`（cwd 来自会话）；路径一律 canonical 化后限制在 cwd 内（复用 manager 现有 guard 思路）。
- 新配置：`ACP_MAX_TERMINALS`（默认 5）、终端重连缓冲时长。
- 边界处理：无 upstream（标注并退化）、detached HEAD、非 git 仓库 → 诚实空态。
- 终端 = 本机任意命令执行面。服务仅监听 127.0.0.1、与 agent 已有权限面同级，但须写入 README 安全姿态一节。
