# ADR-007：多租户隔离与项目管理

日期：2026-08-17　状态：已采纳

## 背景

macOS 桌面版有「允许局域网访问」开关（adr-004），打开后局域网内任何设备都能用完整 web 端。此前系统**零身份**：没有登录、没有归属，谁进来都看得见全部会话、能浏览整台机器的目录、能开终端。局域网分享要真正可用，必须先有租户隔离。

用户诉求两条：

1. **以会话为主的隔离**——每个人只看得见自己的会话。
2. **工作目录的最上层限制**——每个人只能在分配给自己的目录树里干活。

外加一条项目管理：仓库克隆到用户目录下，进入仓库（项目）开会话。

## 产品形态（用户拍板）

| 维度 | 决策 |
| --- | --- |
| 身份建立 | owner 发邀请链接。owner 自己 = 本机访问（loopback），不需要任何凭证 |
| 目录根 | 自动按租户建 `~/acpp/<租户>`，一切路径面在此落闸 |
| 共享资源 | 技能库、角色、内置工具配置**全局共享**：owner 可写，租户只读 |
| 隔离资源 | 会话记录各看各的；owner 看得见全部 |
| 编排 | **不对租户开放**（owner 专属） |
| 终端 | 对租户开放（明确接受其越权面，见下） |
| 项目 | 租户 root 下的两层目录 `<组织>/<仓库>`，如 `~/acpp/luca/BDBGAME2024/pp-game` |
| 仓库清单 | gh 可访问的全部仓库，**排除个人账号名下的** |

## 决策

### 1. 身份载体是 HttpOnly Cookie，不是 Authorization header

系统有三条通道要鉴权：REST（fetch）、SSE（`EventSource`）、终端（WebSocket）。后两者**都带不了自定义 header**——`EventSource` 没有 headers 参数，浏览器 WebSocket 同理。若走 header，SSE 与终端就得把 token 放进 query string，等于让凭证进日志、进 Referer。

Cookie 是唯一能让三条通道统一鉴权的载体：`HttpOnly` + `SameSite=Lax` + 一年有效期。邀请链接 `http://<ip>:<port>/?invite=<token>` 由前端读出后调 `POST /api/auth/redeem` 兑换成 cookie，随即从地址栏抹掉 token（`history.replaceState`），避免用户把带凭证的 URL 转发出去。

不上 HTTPS，因此 cookie 不设 `Secure`——局域网明文本来就是这个部署形态的前提（README §安全姿态 已声明）。

### 2. owner 判定用 loopback，不发 owner 凭证

`RemoteAddr` 是回环地址（127.0.0.1 / ::1）即 owner。理由：桌面版壳与主机浏览器天然从本机访问，判定零配置、不会丢、不需要维护一份「owner 密码」。局域网设备的 RemoteAddr 一定是局域网 IP，拿不到 owner 身份。

代价：owner 从别的设备访问时只是一个普通租户。可接受——owner 就坐在这台机器前。

### 3. 隔离在中间件与 service 两层落闸，不靠 handler 自觉

- **中间件**（`httpapi/auth.go`）：解析身份 → 放进 request context。未认证请求除白名单（`/api/health`、`/api/auth/*`、`/api/mcp/*`）一律 401。
- **owner-only 端点**：编排全部、系统面（数据目录/环境安装/自更新）、技能与角色与 agent 的**写**操作、租户管理。中间件按路径前缀 + 方法判定，不散落在 handler 里。
- **归属校验**：会话相关端点在 service 层按 `TenantID` 过滤，owner 传 `nil` 过滤器看全部。**不是** handler 里 if 一下——查询本身就带条件，漏写等于查不到，不会变成越权。
- **路径闸**（`service.PathGuard`）：目录浏览、建目录、会话 cwd、@ 文件引用、工作区文件树/预览/git、终端 cwd、项目操作，全部先过同一个 guard：canonical 化后必须落在租户 root 内。owner 的 guard 是恒真。

`/api/mcp/{token}` 走豁免：那是 agent 子进程回连的端点，本来就用一次性 token 鉴权（adr-006），加 cookie 反而拉不起来。

### 4. 项目 = 磁盘目录，不入库

跟技能库同一套哲学（README §技能库）：磁盘即事实源。项目列表 = 扫租户 root 下深度 2 的目录，读 `.git/config` 拿 remote、读 HEAD 拿分支。不建表、不加外键、不做同步——用户在终端里 `git clone` 出来的目录，刷新页面就是一个项目。

会话与项目的关联同样不靠外键，靠 **cwd 前缀匹配**：会话 cwd 落在哪个项目目录下就属于哪个项目。改名、移动目录都不会留下悬空引用。

**目录形状固定为 `<root>/<组织>/<仓库>`**（两层）。这是 clone 的落地结构，也是手建项目的形状——统一后「项目名」天然就是 `组织/仓库`，与 GitHub 的心智一致。

### 5. 租户 clone 禁用 git credential helper

`git clone` 默认会走 credential helper（macOS 钥匙串），也就是**owner 的凭证**。若不禁用，任何租户都能借 owner 的身份拉走 owner 有权访问的任何私有仓库——包括不在可选清单里的。

因此租户的 clone 一律加 `-c credential.helper=` 与 `GIT_TERMINAL_PROMPT=0`：拉不到就是拉不到，不会静默借用凭证，也不会卡在等待输入。owner 自己 clone 不做这个限制。

仓库清单走 `gh api /user/repos?affiliation=organization_member,collaborator`——`affiliation` 不含 `owner`，个人账号名下的仓库天然不出现。清单接口对租户开放（只读列表），但**克隆的私有仓库仍需租户自己有权**，因为凭证被禁用了。这一条是刻意的双保险：清单是可见性控制，凭证是能力控制。

## 诚实的边界

隔离对**界面**是硬的，对**执行**是软的：

- 租户拿到工作区终端 = 本机任意命令执行，`cd /` 就出了 root。用户明确选择开放终端，接受这一点。
- agent 自带 shell（codex 的 shell 工具、claude 批准后的 Bash）同样不受 root 约束——README §安全姿态 早已声明 fs 代理不是可靠拦截点。

也就是说：**本方案防的是「看见别人的东西」与「误操作走出自己的目录」，不防「有意越权的人」**。真正的执行隔离需要 OS 级沙箱（每租户一个 macOS 用户 / 容器），不在本 ADR 范围。局域网共享的前提仍是可信网络。

## 数据模型

新增一张表，两处加列：

- **Tenant** — `name`（唯一）、`token`（邀请与会话凭证，uniqueIndex，只对 owner 可见）、`root`（绝对路径）、`disabled`、`lastSeenAt`。
- **Session.TenantID** — `0` = owner。索引 + 全部查询带条件。
- **OrchSession** 不加列：编排是 owner 专属，天然单租户。
