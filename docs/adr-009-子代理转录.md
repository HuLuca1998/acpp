# ADR-009：把 agent 自己派的子代理变成可看的清单

日期：2026-08-19　状态：已采纳

## 背景

[adr-006](adr-006-编排-外化子代理.md) 用「编排会话」解决了子代理黑盒问题——但它的办法是
**换掉**子代理：主会话经我方 MCP 派活，子会话由我们全权托管，代价是用户得主动切到编排页、
还要先配角色。

普通会话页没被覆盖：那里 agent 用的是自己的 Task/Agent 工具，我们只是旁观者，界面上只有
一张工具调用卡片。`disallowedTools:["Task"]` 只加在编排主会话上，普通会话照旧。

这不是边角场景——本机 2414 个 codex 会话里 356 个（15%）有子代理活动，claude 侧只会更高频。

## 实测依据（2026-08-19 真机，claude-agent-acp 0.63.0 / codex-acp 1.1.7）

八组实测，结论全部来自真派子代理抓的 wire，不是读文档推的：

1. **两端机制截然不同**。claude 把子代理的工具调用混进主流，靠 `_meta.claudeCode.parentToolUseId`
   认领；codex 的子代理是**独立 thread**，主流里只有一条 `subAgentActivity`，转录留在自己的
   rollout 文件里。
2. **claude 不声明能力也会推子代理的工具调用**。`subagent-transcript` 只控制正文与思考的转发，
   `tool_use` 无条件推送——也就是说 acpp 一直在把子代理干的活显示成主 agent 干的。
3. **归属标记会漏带**。同一次工具调用的部分后续 update 会把 `parentToolUseId` 连同 `subagent`
   标记一起丢掉，归属必须按 `toolCallId` 记住，不能每条现读现判。
4. **父子链可还原任意深度**。实测两层嵌套，第二层 Agent 卡片的 `parentToolUseId` 正是第一层的
   卡片 id。claude 的磁盘 meta 还带 `parentAgentId` 与 `spawnDepth`。
5. **并行子代理事件严重交错**，但分流可靠；后台子代理（`run_in_background`）形状与前台无差别。
6. **claude 的 `session/load` 零重放子代理转录**——协议层补不回历史。但转录持久化在
   `~/.claude/projects/<cwd>/<sessionId>/subagents/agent-<agentId>.jsonl`，实时流式写入。
7. **codex 运行中即可 `session/load` 子 thread**，内容随时间增长，不必等它跑完。
8. **codex 的子 thread fork 了父会话全部历史**：41 条重放里 34 条是父会话重演，且 ACP 层
   **没有任何标记能区分分界点**（messageId 父子重合、`_meta` 只有 phase）。

## 决策

### 只做「派了什么 → 拿回什么」，不做过程

不声明 `subagent-transcript`。理由是它换来的是子代理的正文与思考——那是过程，而面板要回答的
是「派出去的活怎么样了」。声明了反而要处理更多混进主流的内容，且 claude 的历史补不回来（结论 6），
形态还会与 codex 不对等。

这个取舍同时绕开了 codex 的 fork 污染（结论 8）：只取子 thread 的最后一条 final_answer，
它必定是子代理自己的汇报，不必区分分界点。

### 形态

工作区新增「子代理」面板，与文件树/分支同待遇（默认隐藏、⋯ 菜单开、随意拖放）。按
进行中/已完成/失败三组分列，**进行中不给折叠**——正在跑的东西没有藏起来的道理。明细走手风琴，
同时只摊开一条，长输出不会把列表顶散。

子代理干活的工具调用同时从主对话流摘走（结论 2 的既有问题一并修掉）。

### 两端取数

| | claude | codex |
| --- | --- | --- |
| 条目来源 | 带 `subagent:true` 的 Agent/Task 调用 | `subAgentActivity` 事件 |
| 输入（简报） | `rawInput.prompt`，完整原文 | **拿不到**——`spawn_agent` 的 message 是 Fernet 密文 |
| 输出 | `rawOutput`，随工具调用直接下发 | 展开时 `session/load(threadId)` 懒加载 |

codex 的输入是唯一硬缺口，界面如实显示「该 agent 不提供此项内容」，不装作空内容。

为 codex 的按需读取给 `acp.OpenOptions` 加了 `ReplayEvents`：常规会话必须抑制 `session/load`
的重放（历史的正源是转录与重建），而这种一次性读取要的就是那批内容。

### 存储零改动

转录由 WireTap **原样**追加 JSON-RPC，`_meta` 一直都在。重建器开始解析它之后，历史会话同样能
还原出子代理清单——不需要新表、不需要改消息模型。

## 后果

- 与 adr-006 是互补关系：编排页管「我们托管的子代理」，本面板管「agent 自己派的」。两条路线都保留。
- 面板只认协议里的东西。claude 磁盘上那份完整转录（结论 6）暂不读——那是私有存储布局，
  会随版本变；真要做过程回放时再评估。
- codex 的输入缺口只能等上游：`collabAgentToolCall` 带明文 prompt，但它属 `multi_agent_v2`，
  本机 2414 个会话里出现 0 次，flag 当前关闭。
