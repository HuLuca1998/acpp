# ADR-025：套餐用量的取数路径

日期：2026-09-22 · 状态：已采纳

## 背景

用户要在对话页底部的用量圆环里看到与 Claude 桌面 app 用量面板同样的东西：
5 小时窗用了几成、本周用了几成、什么时候重置——**账号在订阅套餐上的水位**，
codex 也要有一份。它与 [用量报表](adr-013-通知体系.md) 那套账本是两件事：账本
记的是这台机器花了多少 token（本地能算），水位是账号在服务端还剩多少（只有
服务端知道）。ACP 协议本身不给这个：`usage_update` 只有上下文窗口的 `{used, size}`。

## 候选路径（2026-09-22 实测）

### claude

| 路径 | 结果 |
| --- | --- |
| 直接打 `api.anthropic.com/api/oauth/usage`，令牌从钥匙串 `Claude Code-credentials` 取 | 数据全，但令牌**几小时就过期**（实测早上第一次打开就是 401 "OAuth access token has expired"）。要自己拿 refresh token 去刷——refresh token 是轮换的，与本机 CLI / 桌面 app 抢着刷，抢输的一方被登出。不想碰这个雷 |
| ACP 会话里 adapter 转发的 `usage_update._meta["_claude/rateLimit"]`（SDK 的 `rate_limit_event`） | 免费、实时，但**一次只给一个窗口**（`rateLimitType` + `utilization`，是当前最紧的那个），且只在轮进行中出现。做主数据源不够，做增量刷新可以 |
| `claude -p --input-format stream-json --output-format stream-json`，往 stdin 发 `{"type":"control_request","request":{"subtype":"get_usage"}}` | **采用**。返回 SDK 的 `SDKControlGetUsageResponse`：`subscription_type`、`rate_limits.limits[]`（session / weekly_all / weekly_scoped，带 percent、resets_at、is_active、scope.model.display_name——桌面 app 画的就是这张表）、`extra_usage`。**令牌过期由 CLI 按官方路径刷新**：实测用过期钥匙串跑一次，数据照拿、钥匙串顺手被续上。耗时 2.5 秒 |

采用路径的启动参数：`--setting-sources ""`（不加载用户设置，否则 SessionStart
钩子会跑一遍）、`--strict-mcp-config --mcp-config '{"mcpServers":{}}'`（不起任何
MCP 服务器）、工作目录放临时目录（不在 `~/.claude/projects` 给本项目留空会话）、
摘掉 `CLAUDECODE` 等嵌套标记（从 agent 终端起的后端会把它们传下来，CLI 见了拒绝服务）。

### codex

| 路径 | 结果 |
| --- | --- |
| codex-acp 的 `account/rateLimits/updated`（1.10 起） | adapter 只存在会话状态里给 `/status` 用，不经 ACP 通知转发；且只在轮进行中出现 |
| `GET https://chatgpt.com/backend-api/wham/usage`，头带 `Authorization: Bearer <auth.json 的 access_token>` 与 `ChatGPT-Account-Id` | **采用**。codex CLI 的 `/status` 就是从这里拿的。返回 `plan_type`、`rate_limit.primary_window / secondary_window`（`used_percent`、`limit_window_seconds`、`reset_at`）、`credits.balance`。UA 随意，账号头可省但照带。令牌是 JWT，`exp` 以周计；本地先看 `exp`，过期直接报 `expired` 不去打（**不自己刷新**，理由同 claude），用户跑一次 codex 就续上 |

`auth.json` 用 acpp 的 `<dataDir>/codex-home/auth.json`（软链系统登录态），
codex-home 还没搭起来时退到 `~/.codex`。

## 决策

1. 新端点 `GET /api/system/quota?flavor=claude|codex`（`system` 包，见 README §API）：
   两家各自取数、归一成同一个 `PlanQuota`（`windows[]` 的 `kind` 归成
   session / weekly / weekly_model，codex 按窗口秒数归类），后端缓存一分钟、
   同一方言并发只跑一次，`?refresh=1` 绕过。
2. **不碰任何凭证的刷新**：claude 走 CLI，codex 只读 `auth.json`。过期就如实报
   `expired` 并给「跑一次 CLI」的引导。
3. 界面落在用量圆环的弹层里（`chat/composer/quota-section.tsx`）：上下文水位之下、
   本轮明细之上；claude / codex 会话（含草稿态）才显示，圆环因此在草稿态也在。
4. codex 的额度是**账号**的：acpp 里的 codex 若配了第三方 provider（`config.toml`
   顶层 `model_provider` 不是 openai），消耗的不是这份额度——响应带 `provider`，
   界面说明白，免得用户对着 100% 纳闷为什么还能发。
5. 对租户开放（`isOwnerOnly` 里单列）：他们花的是同一份额度，见底时得知道为什么
   发不出去；响应里只有套餐名与百分比，没有账号信息。

## 代价与边界

- `get_usage` 是 SDK 标为实验的控制请求（`sdk.d.ts` 里方法名带着
  `DO_NOT_RELY_ON_THIS_API_YET`），形状变了 `quota_claude.go` 跟着改；测试夹具
  `testdata/claude-usage.json` 是 2.1.258 的真实回包，升级后对一眼。
- claude 那条路每次拉一个进程（2.5 秒 + 一次远端请求），靠一分钟缓存兜；
  面板打开即拉、不做后台轮询。
- ACP 会话里的 `_claude/rateLimit` 增量没有接：接了能在轮进行中实时更新
  「当前最紧的那个窗口」，是后续可选的增强，不影响现在的快照面。
- Linux 后端也走 CLI（凭证在 `~/.claude/.credentials.json`，同样由 CLI 管），
  没有平台分支。
