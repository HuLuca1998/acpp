# ADR-020：Discord 定时任务——到点开子区跑全新会话，agent 自建任务

- 日期：2026-09-03
- 状态：已落地
- 相关：[定时任务设计调研](定时任务-设计调研.md)（openclaw 源码分析与方案推导，本篇是它的决策结论）、[adr-016](adr-016-discord-频道工作区.md) / [adr-017](adr-017-discord-子区对话.md) / [adr-018](adr-018-discord-工作树与数据库绑定.md) / [adr-019](adr-019-服务器观察能力.md)

## 背景

两个用户场景：在 Discord 里让 AI 出一份用户七日行为报告，然后说「每天早上 10 点发到这个频道」；
让 AI 巡检服务器错误日志与慢查询，有事再汇报。acpp 缺的只是调度器、任务模型、
「没有人发消息时怎么起一轮」与 agent 自建任务的工具面——环境定义（频道绑定）、
运行管线（子区对话）、工具面与交付都是现成的。

## 决策

1. **任务挂在频道绑定上。** 任务只存「什么时候、干什么」（cron + tz + prompt），环境跟随绑定运行时现读；两处存等于两处漂移。频道解绑时任务一并删除。
2. **一次运行 = 起始消息 + 子区 + 全新会话。** 起始消息扮演用户那条 `@acpp`，往下全是现成管线；跑完起始消息编辑成状态与摘要，子区可续聊。与 openclaw 的 isolated 会话同构，多出来的一条是可续聊。跑完即关会话释放席位（续聊 `session/load`）。
3. **无人值守契约**注入会话提示词（claude）与开场输入（两端）：不提问、交成品、避开审批、无事 `NO_REPORT`、失败如实报。提问后端直接取消；权限卡 @ 创建者。开场同时注入运行时事实（几点、上次运行与摘要）。
4. **调度核心是叶子包 `internal/schedule`**，不认识 discord：Runner 与 Scope 由调用方注入，网页会话侧要定时时再接一个 Runner。存储是它自己的 `<dataDir>/schedule.json`，不塞进 discord.json——两个子系统各自的回退面都还是「删文件」。
5. **agent 自建任务走 `acpp-cron` 工具面**，与 acpp-chat 共用凭证、端点多一段 `-cron`；投递固定为当前频道（从凭证推）。工具描述承担触发词、时区例子与自包含契约；`scheduled-task` 技能承担方法论（先做一次再固化 + 清单 + 两个范本）。
6. **失败策略比 openclaw 保守**：退避 5m/15m/60m，连败 5 次停用并通报（它是 10 次）；bot 断线与池满算忙碌不算失败（一分钟重试，池满先收空闲 2 分钟以上的会话）；重启不补跑但晚 30 分钟内仍跑；整点不错峰。
7. **不做**：main session / heartbeat / systemEvent（acpp 没有常驻主会话）、command / script / stream / 条件触发脚本、webhook、pacing、投递到别的频道。

## 与调研稿的出入

- 任务存 `schedule.json` 而不是 `discord.json`（决策 4）。
- 网页表单只做 cron；一次性任务（`at`）在对话里让 AI 建。
- 起始消息的摘要取回复首行有内容的正文（剥掉标题与加粗），技能里要求首行写结论来兜。

## 后果

- `discord` 包已到 20 个直接源文件的硬线，本次没有新增文件：运行管线进 turn.go、工具面进 toolface.go、命令与卡进 skills.go、管理面进 discord.go。再往这个包加东西之前必须先分包。
- acp 叶子包加了 `ErrPoolFull` 哨兵与 `OpenCount`，供调用方在池满时决定收谁腾位。
- 真机验证（dev bot，Acpp-Test）：对话里一句话建任务 9 秒；手动触发一次运行 7.5 秒出结果；起始消息、子区、运行记录、网页区块全部对上。
