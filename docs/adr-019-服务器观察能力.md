# ADR-019：服务器观察能力

- 日期：2026-09-01
- 状态：拟定
- 相关：[adr-008 数据库数据源](adr-008-数据库数据源.md)（连接管理与工具面的形态照它；本篇**修改**其 SSH 配置的存放方式）、[adr-018 Discord 工作树与数据库绑定](adr-018-discord-工作树与数据库绑定.md)（频道锁定的模式照它）、[adr-010 租户会话能力与 owner 对齐](adr-010-租户会话能力与-owner-对齐.md)

## 背景

AI 在会话里已经有两条事实通道：**代码**（项目怎么发布的，写在 compose /
Makefile / CI 里）与**数据库**（业务数据长什么样，adr-008）。缺的是第三条：
**服务发布之后在服务器上是什么状态**——容器起没起、日志里在报什么、磁盘满没满。

有一件事必须先说清楚，否则整个功能的定位会错：**AI 现在就能看服务器**。
claude 与 codex 自带 shell，一条 `ssh` 就上去了；实测记录在案，
`allowedTools` 不是白名单（它的语义是「自动批准」），能拦的只有
`disallowedTools` 黑名单。所以本功能的价值**不在「能不能连」**，只在四件事：

1. **配置复用** — 不必每次在提问里塞主机、端口、密钥路径。
2. **输出预算** — 生产机上单个日志文件能到几百 MB，一次 `grep` 就把上下文
   灌爆。工具能在服务端截断、能聚合。
3. **成本护栏** — 生产机负载常年不低，一次莽撞的全盘 `grep` 能把服务打出
   问题。工具能强制 `timeout` / `nice` / 提前中断。
4. **留痕** — 走 MCP 的调用进 `mcpcall`，工具台看得见；Bash 里的 ssh 不进
   任何账本。

## 决策

### 一、三层分工：代码是事实源，skill 是方法论，MCP 是通用原语

```
项目代码（事实源）          skill（方法论）           MCP（通用原语）
docker-compose.yaml   ──→  怎么从代码推断远程    ──→  server_ls / server_read
deploy/ Makefile / CI      路径、容器名、日志位置     server_grep / docker_*
日志配置（zap 等）     ──→  该读哪些、怎么省着读  ──→  照推断去实际读
```

**MCP 工具里不出现任何具体项目的知识**。项目的发布方式千差万别（compose /
systemd / 裸进程 / k8s），把「日志在 `<某目录>/log/<服务>/<日期>/`」这类结构
编进工具，等于给一个项目写死。AI 手里有代码，让它自己推断远程布局，再用
原语去验证——推断错了会当场暴露，比工具里一份过期的硬编码安全。

一个关键闭环：`docker_inspect` 返回的 compose label
（`com.docker.compose.project.working_dir`）**直接给出远程项目根目录**。AI
拿它与代码里的 compose 文件一对，代码与服务器就接上了。

第二条原则：**工具形状对标 AI 已有的本地工具**。`server_read` 的
`offset`/`limit` 照 `Read`，`server_grep` 的 `pattern`/`context` 照 `Grep`。
同一套心智模型的远程版，模型不用学新东西。

### 二、服务器是底座，数据源引用它

新建 `model.Server`：

```
Name（唯一标识，AI 用它指定机器）/ Host / Port / User
Auth（password | key | both，照 Navicat 三选一）/ Password / KeyPath / Passphrase
Note（用途说明，**会给 AI 看**）/ Disabled
```

**数据源的 SSH 配置改为外键引用服务器**（`DataSource.ServerID`），不再各自
存一份主机地址与凭证。理由是这两件事本来就是一回事：**跳板机就是一台我有
SSH 权限的机器**，和「要观察的服务器」没有区别。分开存的话，同一台机器要
在两个地方各配一遍凭证，改端口要改两处，而且没有任何一处知道它们是同一台。

迁移（启动时一次性，幂等）：遍历 `SSHEnabled=true && ServerID=0` 的数据源，
按 `(Host, Port, User)` 去重建 `Server`（Name 取 host，冲突补 `-2`、`-3`；
Note 写明「自 数据源 `<ref>` 的 SSH 配置迁移」），再回填 `ServerID`。
旧的 `SSH*` 列**保留但停止读写**（在模型上标注废弃）——GORM AutoMigrate
不删列，留着是版本回滚时的后路，删了才是不可逆的。

**不做项目隔离**（与 adr-008 的数据源刻意不同）：一台服务器上跑着多个项目
是常态，本功能的用途就是「让 AI 自主观察这台机器」，按项目切会把它自己需要
的上下文也切掉。所有启用的服务器对所有会话可见，路径不限。`Note` 承担「这台
是干嘛的」，AI 靠它选机器。

> 以后想收窄的钩子：加一个可选 `Project` 字段并在 `MountsFor` 里过滤即可，
> 模型不用动。

**SSH 拨号提为公共叶子包 `internal/sshdial`**：认证三选一、known_hosts 校验
（含 skeema/knownhosts 那个算法协商的坑）现在被 `datasource` 与新包同时需要，
按 AGENTS.md §1.5 该提独立包。服务器查询本身住 `internal/remote`。

本轮**不支持跳板机多跳**：现有场景都是直连，模型上以后补两个字段即可，
不用推翻。

### 三、工具清单

MCP server 名 `acpp-server`，**全部只读**（`readOnlyHint: true`），claude 侧
预批不弹权限卡——观察类工具一轮排障要调十几次，每次弹卡没有意义。

**P0（核心七个）**

| 工具 | 参数 | 返回 | 护栏 |
| --- | --- | --- | --- |
| `server_hosts` | — | 已配服务器：name / host / note | 对应 `db_sources`，不知道连哪台时先调它。**不测连通性**——那要真连一遍，太慢；连不上由实际调用时报出来 |
| `server_info` | `server` | OS、内核、uptime、CPU 核数与负载、内存、各挂载点磁盘、网络流量、时间与时区 | 一次给全景，不拆成四个工具；服务端拼成一条命令跑完 |
| `server_ls` | `server` `path` `depth`=1 `pattern` `sort` `limit`=200 | 名称/类型/大小/mtime/权限，软链标目标 | depth 硬顶 3；limit 硬顶 1000 |
| `server_read` | `server` `path` `offset` `limit`=200 `tail` | 带行号内容 + 总行数与文件大小 | 单次 ≤64KB；二进制拒绝并说明；超限提示改用 tail/grep |
| `server_grep` | `server` `path` `pattern` `ignore_case` `context` `include` `max_matches`=50 | `文件:行号:内容` | max_matches 硬顶 200；服务端 `grep -m` 提前中断 + `timeout` + `nice/ionice`；目录搜索必须给 `include` 或受 depth 约束 |
| `docker_ps` | `server` `all` `filter` | 名称/镜像/状态/运行时长/**重启次数**/健康/端口 | 重启次数与健康状态是排障第一现场 |
| `docker_logs` | `server` `container` `tail`=200 `since` `until` `grep` `timestamps` | 日志行 | tail 硬顶 2000；输出 ≤64KB |

`server_read` 的 `tail` 是一等参数，不是可选修饰：看日志最常用的动作就是它，
把它做成显眼的参数，AI 才不会去 `offset` 一个几十万行的文件。

**P1（补完）**

| 工具 | 说明 |
| --- | --- |
| `docker_inspect` | 精简详情：挂载、**compose label**、命令、工作目录、重启策略、健康检查历史、退出码、OOM 标志、网络模式。环境变量脱敏后给 |
| `docker_stats` | CPU% / 内存 / 网络 IO / 块 IO / PID 数（`--no-stream`，约 1–2 秒） |
| `server_ps` | 宿主进程：`sort`=cpu\|mem，`limit`=20。nginx、mysql 这类跑在宿主上的进程 `docker_stats` 看不到 |
| `server_ports` | 监听端口与进程。确认服务起没起、发现内部端口 |
| `server_journal` | systemd 日志：`unit` `since` `lines` `grep`。日志的第三种形态 |

**不提供 `server_exec`**。给了裸命令通道，上面十二个工具的护栏与输出预算就
全废了——模型总会倾向最灵活的那个。工具的全部价值就在「有形状、有预算」。
AI 真需要任意命令时它自带 shell，那是用户在权限卡上能看见的显式选择。

`server_http`（从服务器内部发 HTTP，用于健康端点与 pprof）本轮不做。

### 四、挂载与引用：照数据库那套

- **有启用的服务器就挂** `acpp-server`（一台都没有则完全不挂，免得工具清单
  里多十几个用不了的条目）。不按项目过滤。
- **挂的只有工具，没有提示词**。用户 `@` 引用某台服务器时，才随引用下发一个
  **resource 块**（服务器标识 + 用法规矩），照 `AppendDBReferences` 的形状。
  **绝不能加裸 text 块**——转录重建时所有 text 块会被拼成用户正文，注入的
  说明会显示成用户自己说的话（datasource 那边踩过，`legacyDBGuidance` 至今
  留着兼容）。
- **引用粒度是「一台机器」**，不带路径。`@pp-game-live` 的含义是「这次说的是
  这台」，具体看哪个目录由 AI 从代码推断——与「代码是事实源」的主线一致。
- **租户与 owner 一致**（照 adr-010）：服务器工具面对租户开放，管理面（连接
  配置）仍 owner 专属。
- **Discord 频道可锁定一台服务器**（照 adr-018 的数据库环境绑定）：`/init`
  在选库之后加一步选机器，`Binding` 存 `ServerID` + `ServerName` 快照；锁定
  后子区的 `server_hosts` 只列得出那一台。为零时维持全部可见。

### 五、四个必须做对的技术点

1. **命令构造绝不字符串拼接**。SSH 的 exec 只接受一个命令字符串，由服务端
   shell 解析——所有路径与 pattern 参数必须过 `shellQuote`（单引号包裹 +
   内部单引号转义）。这是本功能唯一的注入面，必须有单测覆盖。
2. **连接先一次性**。照 adr-008 的拍板：连接用完即拆，不做池。但排障时 AI
   会连调十几次，每次握手 200–500ms 是实打实的等待——留一个 60 秒空闲缓存的
   接口位，先不实现，实测慢了再开。
3. **输出预算统一 32KB**。超出截断并明写「已截断，共 X 行，用 offset / tail /
   grep 收窄」。**服务端命令自身也要限流**（`head -c` / `grep -m` / `tail -n`）
   ——只在返回值上截断的话，服务器那边已经白干了，护栏就只保护了上下文、没
   保护机器。
4. **环境差异要降级**。busybox 与 GNU 的 `ps`/`ls` 参数不同，`ss` 不在要退
   `netstat`，没装 docker 要回「这台服务器上没有 docker」而不是一堆 stderr。

### 六、skill `server-inspect`

MCP 的通用性靠 skill 补回项目特异性。骨架：

1. **铁律：先读代码，再连服务器**。远程路径的事实源是项目代码——
   `docker-compose*.y*ml`（容器名、挂载、端口、日志驱动）、`Dockerfile` /
   `deploy/`、`Makefile` / `scripts/deploy*` / CI workflow、项目日志配置
   （zap 的 `director` 与 `retention-day`、winston 的 transport）、健康端点。
2. **用 MCP 验证推断，不是替代推断**：`server_hosts` 选机器 → `docker_ps`
   与 compose 比对（drift 检测：跑着的和代码里写的一致吗）→ `docker_inspect`
   的 compose label 确认远程根 → `server_ls` 确认目录真实结构。
3. **按症状的排障路径**：服务没响应 → `docker_ps` 看状态与重启次数 →
   `docker_logs --tail`；定位报错 → `server_grep`（限时间窗 + max_matches）
   → `server_read` 读上下文；资源异常 → `server_info` → `docker_stats` →
   `server_ps`；确认发布 → `docker_ps` 的镜像与启动时间 → `server_ls` 看
   binary 的 mtime。
4. **日志的三种形态**：docker json-file（`docker_logs`）、挂载出来的文件日志
   （从 compose 的 volumes 反查路径）、systemd journald（`server_journal`）。
   很多项目**同时有前两种**，`docker_logs` 只有近期、长期留存在挂载目录里。
5. **成本礼节**：先 `tail` 再考虑 `read`，先 `server_ls` 看大小再决定怎么读；
   `grep` 必须限定文件或 `include` 并给 `max_matches`；重操作前先 `server_info`
   看负载。

**本轮不做自动预置机制**：技能库现在是用户自管的（`<dataDir>/skills/`），
「随软件分发的内置技能」需要先想清楚升级时怎么对待用户的修改，而用户数据
（技能 / 设置）打算另起一个仓库做多设备统一源——那件事定了再一并解决。本轮
把 SKILL.md 写成文档范本，用户自行放进技能库。

## 诚实的边界

**这是闸门不是边界**，与数据库那套同理：工具面挡不住 AI 用自带 shell 直接
ssh 绕过去。真正的边界是 **SSH 账号自身的权限**——要硬保证只读，就给这台
机器配一个受限账号。工具面提供的是默认路径上的形状与预算，不是安全隔离。

**不做项目隔离是显式选择**，不是遗漏：一台机器多个项目时 AI 看得见全部，
配置一台服务器就等于授权 AI 观察整台机器（含 `/root/.ssh/`、各项目的配置与
密钥）。这一条对租户同样成立。
