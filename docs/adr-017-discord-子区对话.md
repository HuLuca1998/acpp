# ADR-017：Discord 子区对话——@bot 开子区，子区里直接与 acp 干活

日期：2026-08-28　状态：已采纳（建立在 [adr-016](adr-016-discord-频道工作区.md) 的频道绑定之上）

## 背景

adr-016 落地了频道 ↔ 仓库工作区的绑定（/init、克隆、模型/思考深度/安全
权限档、频道主题为唯一常驻信息面）。本篇是对话面，用户定的工作逻辑：

1. 绑定频道里 `@bot <问题>`；
2. bot 以那条消息开一个子区（主频道保持干净，只见子区标题）；
3. 子区里直接与 acp 对话——工作目录就是绑定的克隆，模型/思考深度/权限
   档全部沿用绑定（/model /effort /access 随时可改）。

## 决策

### 1. 直接用 internal/acp，但开独立会话池

「不使用会话的一针一线」指的是会话体系（service 层的 Session/Chat/转录/
SSE）；`internal/acp` 是叶子协议客户端（与 gitrepo 同性质），discord 直接
import。但会话池**独立**（`chatMaxSessions=4`、轮超时 30 分钟、空闲 20
分钟回收）——与网页会话池互不挤占，discord 的资源边界自己管。agent 的
启动方式（命令/参数/环境）经 `Deps.AgentRuntime` 注入，包仍不认识
model/db。技能包注入与网页会话同一份（SkillpackDir）。

### 2. 对话记录不落库——Discord 就是转录

子区本身就是完整的对话记录，不进 acpp 的转录体系、不在网页会话列表出现。
唯一落盘的是 `threads`（子区 id → acpSessionId，存 discord.json）：子进程
被空闲回收或服务重启后，凭它 `session/load` 无感恢复上下文。

### 3. 排队式回合，不用 Interject

回合进行中的追加消息**排队**，当前轮结束后合并成下一轮输入。刻意不用
acp 的 Interject——它在两个 runtime 上语义不同（claude 排成独立新轮、
codex 注入当前轮），排队的行为可预期且实现只有一把锁。

### 4. 频道里只出正文

思考、工具调用、计划都不发（频道干净原则）；回合期间用 typing 指示器
（8 秒续一次）表达「在干活」。轮末把正文按 1900 字分段发出，代码围栏被
切开时每段补闭合、下段重开。纯工具轮（没有正文）发一行结束原因。
`/stop` 中止当前回合并清空排队输入。

### 5. 权限与提问是交互卡（第二轮迭代，取代最初的纯文本编号桥）

- **权限申请 = 按钮裁决卡**：选项直接是按钮（allow 类绿、reject 类红），
  点一下即裁决、卡片原地收口（✅/❌ + 由谁 + 时间）；claude 的计划审批
  （PlanReview/ExitPlanMode）同一张卡，计划全文进卡片正文。回复选项编号
  的文本快捷路径保留。
- **提问 = 一次性表单**（第四轮迭代定稿：逐题卡「反复和服务器通信」被
  否，用户拍板「一个表单操作完成全部选择」）：入口卡列出全部题目 +
  「📝 填表回答」按钮，点开一个 modal 全部答完一次提交。每题占一个
  modal 组件——多选 CheckboxGroup(22)、单选 ≤10 项 RadioGroup(21)、
  更多 String Select(3)、纯输入 TextInput(4)；带「其他」的题在其正下方
  紧跟一个可留空的输入框（问题→选项→输入的排布是用户点名的）。多选/
  单选的判定来自 requestedSchema 实测形状：多选是 `type:"array"` +
  `items.anyOf`，单选是顶层 `oneOf`（与 web 端 lib/elicitation.ts 同一
  口径）。modal 一屏最多 5 个组件，claude 单次最多 4 题——常态一页装完，
  >5 题才分页兜底（提交后经「继续填写」按钮翻页）。提交即收口：入口卡
  原地变成逐题「✅ ~~题~~ 答案」的记录卡，不再发多余的确认消息。单题
  提问直接打字回答也有效。
- 组件 custom_id 带随机 nonce，旧卡的残留按钮点了只会得到「已失效」，
  不会误触当前问答。问答在别处（网页/超时）收口时，卡片改灰终态
  （PermissionDone/ElicitationDone 事件驱动）。
- 每子区同时最多一个挂起问答（ACP 语义如此：权限/提问挂起在 prompt
  调用之内，同一会话不会并发多个）。

### 6. 会话功能对齐：附件、计划卡、工具面（数据库 + 报告）

- **消息附件进入对话**：附件一律先落盘到 `<workdir>/.acpp-uploads/`
  （agent 能移动、改名、当素材用），目录登进 `.git/info/exclude` 不脏
  仓库。内容块按类型追加：图片双发 image block + resource_link，≤32KB
  文本内嵌全文（与网页 @ 文件同口径），其余 resource_link 按需读。
  纯附件消息（无文字）也能开子区/进对话。
- **任务计划卡**：agent 的 plan 更新渲染成一回合一张、原地 PATCH 刷新
  的 V2 卡（✅ 划线 / 🔄 加粗 / ⬜ 待办），回合结束卡上即终态，历史回合
  的卡留档；generation 计数防晚到的旧状态盖掉新状态。
- **工具面与网页会话同源**：数据库工具面（datasource）按项目有条件挂，
  报告工具面（report）无条件挂。凭证走 `mcp.PeerTokens` 非会话通道——
  绑 (子区 key, workdir) 存内存，进程重启失效、开会话现领；HandleMCP
  先查它再查会话表，观测记录 sessionID 记 0。report_open 的打开事件按
  子区 key 路由回 discord：子区里发报告卡（标题 + 路径 + 「打开预览」
  链接），预览走 `GET /api/discord/reports/{channelId}?path=…`（软链
  解析后必须落在绑定工作目录内、只放行 .html、CSP sandbox）。

### 7. 消息显示与按需数据库（2026-08-30 迭代）

- **markdown 转译**：agent 回复是标准 markdown，Discord 只认小方言。
  发出前转译（`mdToDiscord`）：表格→等宽代码块（CJK 按 2 宽对齐）、
  ####+ 标题→加粗、`- [ ]`/`- [x]`→☐/✅、`---` 剔除；围栏代码块内
  原样不动。
- **@bot 的集成角色也算 @bot**：自动补全里 bot 用户和同名集成角色并排，
  选到角色时 `mentions` 是空的（`<@&roleId>` 在 `mention_roles`），
  之前完全不响应（真机踩坑两次）。现按 guild 查 `tags.bot_id` 指向
  自己的角色并缓存。
- **数据库工具面按需挂载**：常挂会诱发「平时问答也去查库」（用户反馈），
  改为默认不挂：`/db on|off|status` 显式开关，消息里带 `@db`/`@数据库`
  令牌一步开启（令牌不进 prompt）。切换即关旧会话，下一轮凭
  acpSessionId 无感恢复并带新挂载；开关按子区落盘（Thread.DBEnabled）。
- **权限收口卡压成两行**：决策完成后不留命令全文（用户点名嫌大），
  只留「✅ 选项 · 对象截一行 · 谁批的 · 何时」。

### 8. 用户视角迭代（2026-08-30 下半场）

- **/help**：完整用法卡（@ 对话/附件/数据库/报告/命令表），仅本人可见
  且不自动删；打成纯文本的裸斜杠命令（/help 等）不进对话，回小字提示。
- **工具活动卡**：与计划卡同模式——一回合一张、原地刷新，✅/🔄/❌
  逐行列最近 8 条工具调用（更早折叠成计数）；渲染结果没变不 PATCH。
- **回合小结**：干过活的回合在回复末段附「-# ⏱ 耗时 · 🔧 N 次工具
  调用」；<20s 且无工具的快问快答不带尾巴。
- **排队消息可编辑**：还挂着 ⏳ 的消息编辑即生效（MESSAGE_UPDATE 更新
  队列文本），已进对话的编辑不追溯也不提示。
- **权限收口两行小卡** 与 **@db 按需数据库**（§7）同场验证：自然业务
  提问（不点名工具）下 agent 能自行发现并正确使用 db_* 工具。

### 9. 子区归属的判定与收养

MESSAGE_CREATE 不带 parent 信息，第一次见到的 channel id 现查一次 REST
（结论含负缓存）。绑定频道下**用户手动开的子区同样收养**——判定标准是
「绑定频道的子区」而不是「bot 开的子区」。

## 后果

- gateway intents 加 GUILD_MESSAGES + MESSAGE_CONTENT（特权 intent，
  开发者门户已开）。
- 主频道的非 @ 消息一律不响应；未绑定频道的 @ 同样沉默。
- 绑定改仓库后，已开的子区会话仍在旧 cwd 上（会话粘住打开时的目录）；
  子进程回收后的下一轮才落到新目录。可接受——重绑是低频动作。
- 单条回合上限 30 分钟（含挂起的问答），超时按失败回报。
